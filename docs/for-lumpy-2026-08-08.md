## 0. The one thing to read before touching anything: the `os` seam

Steps in `gametree.json` now accept **`{"os": "posix"|"nt"}`** and are SKIPPED where they do not
match `os.name`. That is how both machines' versions of an edge now live side by side instead of
one overwriting the other.

```json
{"click_text": "Continue", "window": "Raves of Qud", "os": "posix"},
{"click":      [958, 578], "window": "Raves of Qud", "os": "nt"}
```

Fourteen edges carry it. `tools/selftest_plan.py` enforces the rule that makes it safe: **an edge
must keep at least one ACTUATING step under every os.** An edge whose steps all skip themselves
away runs, does nothing, and reports ok — so that case fails the selftest instead.

Your coordinate versions of the edges are preserved under `"os": "nt"`. Nothing of yours was
deleted. Run `python3 tools/selftest_plan.py` after any edit to the tree.

## 1. Do Raves' letter-key status edges work on Windows now? ← the big one

**This decides whether half the seam can be deleted.**

You rewrote seven edges (`status_skills/attributes/equipment/tinkering/journal/quests/reputation`)
from a per-screen letter key to `F2` + a coordinate tab click, with the note:

> "Raves opens the status overlay with F2 and you pick a TAB — it does not implement Qud's
> per-screen letter bindings (e/k/x/n/j/q), which is what this edge used to send, so it reported
> every step OK and never arrived."

**That premise is false about the source.** `raves-of-qud/godot/MainFrame.gd:282`:

```gdscript
const STATUS_TAB_KEYS := {KEY_K: "skills", KEY_X: "attributes", KEY_TAB: "attributes",
	KEY_E: "equipment", KEY_I: "equipment", KEY_N: "tinkering", KEY_J: "journal",
	KEY_Q: "quests"}
```

plus a `Ctrl+F` branch at `:249` for reputation. All seven are bound, and the Mac drives them
green (whole-tree tour, 2026-08-08, all eight status nodes arrived).

So the real cause on your side was almost certainly key **delivery**, not the binding — and
**your own branch fixed exactly that**: the commit noting that "a `KEYEVENTF_SCANCODE` modifier
press is invisible to Godot (Godot tracks modifiers from key MESSAGES and wants the VK form), so
hv now emits BOTH forms." My guess is that fix landed *after* you rewrote these edges. I have not
confirmed the ordering, so it is a guess.

**Please test:** with the VK fix in place, drive Raves' status tabs with the plain letter keys.

```bash

hv key "Raves of Qud" k     # skills
hv state
hv key "Raves of Qud" escape
hv key "Raves of Qud" e     # equipment ... and j / q / n / x, and ctrl+f for reputation
```

- **If they work** → delete the `"os": "nt"` steps from those seven edges; the seam collapses
  there and both machines go back to one implementation. Keep the `timeout: 15` (yours, and an
  improvement over the old 8).
- **If they still fail** → leave the seam as is and say what the failure looks like. That is a
  legitimate platform difference and the seam exists for it.

Note: `status_messagelog` has **no** letter binding in either app, so it is coordinates on both
sides with no seam. Your `1615 → 1619` re-measure was taken.

## 3. The "Mod Configuration Differs" popup — please exercise it once

I rewrote `loadsave`'s answer to this popup. **The old code was a hazard:** it fired
`{"action":"option","index":1}` at whatever modal was up whenever `"popup"` appeared in the scene
name — and *every* Qud modal satisfies that, because the heartbeat sets `scene` from the raw view
name. Index 1 is a different button on a different modal, and this popup's *pre-selected* option
relaunches Qud **with our bridge disabled** — the exact failure you already paid for once.

It now matches on the popup's **text** ("mod configuration") and picks the option by **its label**
("keeping current"), never by position. It is covered by 11 fake-bridge cases in
`tools/selftest_evaluate.py`, including the reordered-options case that the old index-1 code got
exactly wrong.

But **the real popup only arises from a save whose mod configuration differs, which is a
Lumpy-side condition.** I could not exercise it end to end. Please run `hv loadsave <that save>`
once against a save made without the bridge and confirm it picks "Load keeping current mod
configuration" and the bridge stays up.

If it declines instead, it will say what it saw — that message is the useful bit, please paste it.

## 5. Does the Map Editor context menu work on Windows?

Your feature, and **it does not work on the Mac.** The Mac had no middle button at all, so the
plan had recorded it as untestable; I implemented one in `backends/darwin.py`
(`kCGEventOtherMouseDown` + `kCGMouseButtonCenter`), which made it testable — and it fails.

Measured, same cell, Raves frontmost, an `AgateWall` painted under the cursor:

| gesture | result on macOS |
|---|---|
| left click | works (`Selected Cell: 36, 10`) |
| Ctrl+left (paint from palette) | works |
| Shift+left (region select) | works |
| **right click** (your eraser, `_erase_top`) | **nothing** |
| **middle click** (`_open_context`) | **nothing** |

Ruled out: not the backend and not the OS (Cmd+right-click **in-game** opens the FeedbackTool
form, so right-button events reach Raves fine); not an `_input`-level consumer (`FeedbackTool`
returns early unless right+meta, `Main.gd`'s right/middle camera-pan branch is in
`_unhandled_input`, which runs *after* `gui_input`); not a coordinate miss. So it is inside
`MapEditorScreen.gd`'s own canvas path (`:895` wires `_canvas.gui_input`, handler at `:1027`,
right at `:1039`, middle at `:1043`) and I have not explained it.

**Just tell me whether right-click and middle-click work in the Map Editor on your machine.** If
they work there, it is a macOS/Godot input difference and I will chase it here. If they fail there
too, it is a plain bug in the handler and you are better placed to see it.

Two false trails I hit, so you do not repeat them: Ctrl+click *does* work — my first test only
looked broken because the brush was **AcidGas**, a gas, which paints no visible pixels; use a
wall. And driving that canvas needs **`hv mouse <win> x y` before the click**, or Godot never
updates its cursor and the editor sits at `Mouse Position: 0, 0` while every click reports success.

## Also worth knowing (no action needed)

- **`tools/tour.py` is new** — the whole-tree tour, which had been re-typed as ad-hoc shell every
  session. `tour.py raves`, `tour.py qud --reload <save>`, `--only status_`. Arrival is decided by
  `hv assert`'s **`passed`** field, never by `goto`'s exit code. (Its own first run reported
  0/8 EDGE because I read `ok` — the envelope — instead of `passed`. It now refuses to guess, and
  warns when a run fails *everything*, since that is nearly always a broken harness.)
- **`hv layout pair` now exists.** `parity.py`'s size-mismatch message has been telling people to
  run it for weeks and it was not defined. On the Mac it is Raves and Qud stacked, both 1920×1080,
  **no overlap**. You will want your own local version — layouts are machine-local
  (`~/.config/highvisor/layouts.json`), and `layout-save` grabs *every* window on screen, so trim
  it to the two apps.
- **Overlapping windows cost me an hour.** Qud's toolbar edge failed with the pointer provably on
  target (the hover tooltip was rendering on the right icon) because the two windows overlapped by
  124px and the click landed inside the *Raves* window. If a click-driven edge misbehaves, check
  geometry before focus.
- **Your layout restoration re-applies the last layout on every restart** — good feature, but
  `hv loadsave` restarts Qud and silently resized both windows mid-session here. A capture taken
  after any restart can be off-geometry.
- `plat_mac.py` gained `qud_install_dir()`, so `fonts.py` dropped its
  `getattr(plat, "qud_install_dir", None)` fallback. Verified: it carved 4 faces out of this Mac's
  own install through the unified call.
- `_settle_rendering` now reads the **pid's own sidecar** instead of the shared state file, which
  is a coin flip under duplicate instances.
- `map_editor` had **no `raves` detector** at all (a `qud` entry only), so Raves read as
  `running · unknown screen` and every assert on it timed out. Added.
